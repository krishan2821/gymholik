1. Navigation Architecture & Entry Routing

Gymholik utilizes Expo Router v4 with a hybrid stack-and-tab navigation hierarchy. User entry begins at root _layout.tsx, inspecting the Zustand authentication state before routing.

[App Launch] | +---> [Auth Check: useAuthStore] | +---> Unauthenticated? -> Replace to /(auth)/login | | | +---> Tap 5x on Logo -> /(auth)/super-admin-login | +---> Register Gym -> /(auth)/register (Owner) | +---> Register Trainer -> /(auth)/register (Trainer) | +---> Authenticated? | +---> Role == OWNER / STAFF -> /(tabs) (Home Dashboard) | +---> Role == TRAINER -> /(tabs)/members (My Members)

2. Role-Based Tab Configuration Matrix (tabsByRole)

The single source of truth mobile/src/navigation/tabsByRole.ts defines tab ordering, visibility, and redirection targets:

Role Allowed Tabs (Exact Order) Landing Route Forbidden Routes (Guarded & Hidden)
OWNER 1. Home • 2. Members • 3. Check-in (Center) • 4. Payments • 5. More /(tabs) notes, profile
STAFF 1. Home • 2. Members • 3. Check-in (Center) • 4. Payments • 5. More /(tabs) notes, profile
TRAINER 1. My Members • 2. Check-in (Center) • 3. Notes • 4. Profile /(tabs)/members index (Home money), payments, more, staff, plans, settings, subscription

3. Detailed User Journeys

3.1 Journey 1: Gym Owner Complete Operational Cycle

  1. Launch & Login: Enters phone, password, and gym code. System verifies OWNER role and lands on Dashboard.
  2. Financial Audit: Views Monthly Collection, Today Collection, and Outstanding Dues. Reviews 7-day trend bar graph.
  3. Staff & Plan Configuration:
    • Navigates to More > Plans → Creates "3 Month Gold" with admission fee and duration.
    • Navigates to More > Staff → Adds front-desk staff phone and password.
    • Navigates to More > Trainers → Reviews pending trainer applications and approves with trainer specializations.
  4. Member Admission: Taps Members tab → Taps + Add Member → Uploads photo, selects plan, enters initial payment, confirms receipt.

3.2 Journey 2: Front-Desk Staff Check-In & Fee Collection

  1. Member Check-in:
    • Staff taps center raised Check-in button.
    • Searches member by name or phone. Debounced list surfaces member profile.
    • Taps check-in → System validates membership status.
    • If expired: Modal alert offers instant renewal. If active: Green sage pulse confirms check-in.
  2. Dues Collection:
    • Staff navigates to Payments > Dues.
    • Selects member with balance → Enters collected amount (CASH / UPI) → Submits payment → Generates digital PDF receipt.

3.3 Journey 3: Personal Trainer Client Progression Workflow

  1. Landing: Trainer logs in → Automatically lands on My Members tab (zero access to financial dashboard).
  2. Client Oversight: Views only members assigned to their roster. Selects member to view training bio.
  3. Progress Notes & Weight Tracking:
    • Taps Notes tab → Selects client chip avatar.
    • Views chronological history (Workout, Diet, Progress, Weight logs).
    • Taps Floating Action Button (FAB) + Add Note → Enters current weight and workout adjustments → Saves note.
    • Weight Progress chart dynamically updates point trajectory.
  4. Account Management: Taps Profile tab → Views trainer specializations, gym affiliation, Change Password, and Sign Out.

4. Error & Edge Case Handling Flows

Deep-Link Interception Rule
If a Trainer clicks a deep link targeting /(tabs)/payments or /(tabs)/more, the layout guard immediately intercepts the route and executes router.replace('/(tabs)/members') before any UI renders.
